Image Warping
and Mosaicing

The goal of this project is to combine different views of the same scene into one image. I start by selecting matching points and recovering a homography, then use that transformation to straighten objects and blend overlapping photos into mosaics. In Part B, I replace the manual point selection with corner detection, feature matching, and RANSAC.

Part A / Image warping and mosaicing

A.1 /

Shoot the pictures

Here are the three image pairs I use: Edge Building viewed from a balcony, Zellerbach Hall, and a laptop on a table. Each pair has an overlapping region (about 50%) with recognizable corners and edges, which makes it possible to select the same points in both images.

The idea is to rotate the camera around a fixed center of projection. Under pure rotation, a homography relates the two views. If the camera also translates, a single homography can still align a plane, but objects at other depths may not line up.

A.2 /

Recover homographies

A homography is a 3 × 3 matrix that maps points from one image to another in homogeneous coordinates (8 DOF). It can account for perspective changes, so parallel lines do not have to stay parallel. Straight lines remain straight after the transformation. Since multiplying the whole matrix by a nonzero scalar gives the same mapping, I set its bottom-right entry to 1 and solve for the remaining eight values.

[u, v, w]T = H[x, y, 1]T   ·   x′ = u / w   ·   y′ = v / w

For each match (x, y) → (x′, y′), multiplying through by the denominator gives two linear equations. Stacking these rows for all correspondences forms Ah = b, where h contains the first eight entries of H in row order.

[ x  y  1  0  0  0  −xx′  −yx′ ] h = x′
[ 0  0  0  x  y  1  −xy′  −yy′ ] h = y′

Four point pairs give eight equations, but a small error in a selected point can change the result significantly. I use seven matches for the building, six for Zellerbach, and seven for the laptop. This gives overdetermined systems with 14, 12, and 14 equations respectively, which I solve with np.linalg.lstsq.

A.3 /

Warp the images

Forward warping sends each source pixel into the output, but rounding can leave holes where no pixel lands. Thus, inverse warping is used instead: visit each output pixel, map it back through H−1, divide by its homogeneous coordinate, and sample the source at that location.

I transform all four source corners and take the floor of the minimum coordinates and the ceiling of the maximum coordinates. A translation moves that bounding box to the output origin. The inverse mapping is then (T @ H)−1, where T is that translation matrix. Pixels whose source coordinates fall outside the input remain black.

[u, v, w]T = (T @ H)−1[xout, yout, 1]T   ·   (xsrc, ysrc) = (u/w, v/w)

Nearest neighbor vs. bilinear interpolation

The inverse-mapped location usually falls between pixels. My nearest-neighbor implementation rounds it to the closest pixel and copies that value. My bilinear implementation uses the four surrounding pixels, weighted by the fractional horizontal and vertical distances.

Im(x, y) = (1−a)(1−b)Im00 + a(1−b)Im10 + (1−a)bIm01 + abIm11

Here a = x − floor(x) and b = y − floor(y). Nearest neighbor uses fewer operations but can create jagged edges and aliasing. Bilinear needs four samples and more arithmetic, but produces smoother transitions. It can also soften fine details.

Rectification / Edge Building balcony railing

For rectification, I match four corners of a surface in the original photo to a rectangle that I define by hand. For the railing, the source points are (41, 524), (148, 601), (6, 631), and (124, 700) in the left building photo. I map them to (0, 0), (100, 0), (0, 100), and (100, 100), then sample a 100 × 100 output.

The slanted railing becomes upright in both results. The repeated thin bars make the interpolation difference easy to see: nearest neighbor creates rough, uneven edges, while bilinear smooths them.

Rectification / Zellerbach Cal Performances sign

For the sign, I use points (249, 1174), (459, 1156), (245, 1209), and (460, 1187) in the right Zellerbach photo. The destination points are (0, 0), (200, 0), (0, 35), and (200, 35), with an output shape of 36 × 200.

The sign’s horizontal edges straighten and the text is easier to read across the strip. Bilinear reduces the jagged letter edges, although both results remain blurry because the sign occupies a small region in the source image.

A.4 /

Blend images into a mosaic

I keep the right image as the reference and warp the left image into its projection with bilinear interpolation. The shared canvas includes both the transformed left-image corners and the original right-image corners. I translate both images onto that canvas so negative coordinates do not cut off part of the warped view.

Simply overwriting one photo with the other would create a hard seam. Instead, I build a validity mask for each image and use its distance to the nearest invalid pixel as a blending weight. I pad each mask with zeros before taking the distance transform, so its outer border is treated as a boundary too. The left mask is warped with nearest neighbor to keep it binary.

wL = distance(maskL)   ·   wR = distance(maskR)   ·   mosaic = (wLIL + wRIR) / (wL + wR)

Pixels farther from an image boundary contribute more. Where only one image is valid, that image supplies the result; where neither is valid, the output stays black. Using masks also helps with actual black pixels in a photo not being mistaken for missing image data.

Part B / Feature matching for autostitching

In Part A, I choose the matching points by hand. Here, the goal is to find those correspondences automatically. I use the same three image pairs, detect corners, describe their neighborhoods, and match them across the two views. RANSAC then removes inconsistent matches before the images are warped and blended.

B.1 /

Harris corner detection

A corner has strong intensity changes in both image directions. Harris measures this using a structure matrix M, formed by averaging products of the horizontal and vertical image gradients over a Gaussian-weighted neighborhood.

M = G * [[Ix², IxIy], [IxIy, Iy²]]   ·   R ≈ 2 det(M) / trace(M)

Here Ix and Iy are image gradients, and G is a Gaussian filter. The supplied detector uses this normalized Harris response. Its score is large when both eigenvalues of M are large: intensity changes strongly in two directions. An edge has one small eigenvalue, while a flat region has two small ones, so both receive lower scores.

Keeping only the 500 highest-scoring corners clusters many points around the railings and textured building details. Adaptive Non-Maximal Suppression (ANMS) instead considers how far each corner is from a sufficiently stronger corner. I keep the 500 points with the largest distances, giving a more spread-out set.

ri = min ‖pi − pj‖   over j such that   fi < 0.9 fj

Here f is the Harris response and r is the suppression radius. A large radius means there is no substantially stronger corner nearby.

The top-500 result favors strong details but leaves much of the sky empty. ANMS distributes points more broadly, including weaker points in the sky. Those points are not necessarily useful matches; the next steps compare their appearance and check their geometric consistency.

B.2 /

Feature descriptor extraction

A corner location alone does not tell us which point in the other image it corresponds to. To describe its appearance, I blur the grayscale image with a Gaussian of σ = 2, take a 40 × 40 window around each selected corner, and sample every fifth pixel. This gives an 8 × 8 patch, which I flatten into a 64-value descriptor.

I normalize each patch to zero mean and unit standard deviation so matching depends more on its pattern than its brightness or contrast. The patches are axis-aligned, so they do not account for rotation or scale changes.

descriptor = flatten((patch − mean(patch)) / std(patch))   ·   40 × 40 → 8 × 8 → 64

The patches preserve broad patterns such as dark window edges against a lighter wall. Each grid shows 16 examples from one image; tiles in the same position across the two grids are not matched pairs.

B.3 /

Feature matching

For every descriptor in the left image, I compute its Euclidean distance to all descriptors in the right image. Choosing the nearest one alone is risky: repeated windows or keys can look almost the same. I compare the nearest and second-nearest distances and accept the match only when their ratio is below 0.8.

d1 / d2 < 0.8   ·   d1 = nearest descriptor distance   ·   d2 = second-nearest distance

A small ratio means the best candidate is more distinctive than the next choice. If several points choose the same destination, I keep the match with the lowest ratio. The lines below show the accepted matches before RANSAC.

Many lines connect the same structures, but some jump between unrelated locations, especially in the sky or repeated texture. Similar-looking patches can still be incorrect matches, so I use RANSAC to check whether they agree with one homography.

B.4 /

RANSAC for robust homography

RANSAC (Random Sample Consensus) looks for a homography supported by many matches despite the outliers. In each of 5,000 iterations, I randomly sample four point pairs, solve for H using the same least-squares formulation as Part A, and project every source point into the right image. A match is an inlier if the projected point lands within 3 pixels of its match.

errori = ‖project(Hpi) − p′i‖   ·   inlier if errori < 3 pixels

I keep the homography with the most inliers, then refit H using that set of matches. This gives the final estimate support from many consistent points rather than just the four in one random sample.
